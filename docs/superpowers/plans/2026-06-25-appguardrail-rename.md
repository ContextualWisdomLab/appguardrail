# AppGuardrail Rename Implementation Plan

> Historical archive: this plan records the 2026-06-25 rename work as it was
> executed. Current OpenCode, Strix, and PR review merge scheduling contracts are
> enforced by ContextualWisdomLab organization-level required workflows, not by
> repo-local `scripts/ci/*` governance copies referenced in this archived plan.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved full rename from VibeSec to AppGuardrail so public install, CLI, workflow, documentation, and test surfaces no longer direct users to the third-party PyPI `vibesec` namespace.

**Architecture:** Keep the current single-file CLI architecture for this rename. Rename the public module file to `scanner/cli/appguardrail.py`, update imports/tests/workflows to the new path, and keep any legacy `vibesec` reference limited to intentional migration notes only.

**Tech Stack:** Python 3 CLI using `argparse`, pytest tests, GitHub Actions YAML, shell CI scripts, Markdown docs, CodeGraph CLI/MCP index.

- CodeGraph is required for this implementation. Run `codegraph init -i` before implementation if `.codegraph/` is missing, then run `codegraph status` and require `Index is up to date`.
- Prefer `codegraph_*` MCP tools for structural questions when available. In this desktop session those MCP tools are not exposed, so use the initialized CodeGraph CLI commands `codegraph status`, `codegraph files`, and `codegraph context` as the required structural checkpoint.
- Product name: `AppGuardrail`.
- PyPI distribution name: `appguardrail`.
- CLI command: `appguardrail`.
- Python module name: `appguardrail`.

```python
RULES_CURSOR = """\
# AppGuardrail Security Rules

- Every API route must verify authentication before accessing data.
- For every user-owned resource, verify owner_id matches the current session user.
- Never use SUPABASE_SERVICE_ROLE_KEY or any admin key in client-side code.
- Always verify Stripe webhook signatures with stripe.webhooks.constructEvent.
- Validate all inputs (body, params, query) with a schema library before use.
- Return 403 Forbidden for ownership violations, not 404 or 200.
- File uploads must validate type, size, and filename server-side.
- Never set CORS to allow all origins on authenticated endpoints.
- Add tests for cross-user access denial on every resource endpoint.

See https://github.com/ContextualWisdomLab/appguardrail for full rules and checklists.
"""
```

```python
RULES_CLAUDE = """\
## AppGuardrail Security Guardrails

Apply the following security rules to all code you generate:

2. **Authorization**: Verify resource ownership (owner_id === session.user.id) server-side.
3. **Secrets**: Never use NEXT_PUBLIC_ prefix on secret keys or service role keys.
4. **Input validation**: Validate all inputs with Zod or equivalent before processing.
```
